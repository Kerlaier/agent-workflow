# 02 · 教学型 agent —— 出材料要求

> 用途：派讲义、派练习任务时一起给它。**这几条不是客套，每条都对应一个实测出来的问题。**

```text
出这一课的材料时，按下面来：

1. 练习的「提示」只给思路和关键词，不要给代码。
2. 验收标准是「合上讲义、从空白文件自己写出来」，不是「跑通就行」。
3. 示例尽量贴近真实场景，别用 foo / bar 这种占位。
4. 节奏按 30–45 分钟一站切，一站一个知识点。
5. 材料有更新，告诉工程型 agent 调整时间表。
6. 具体代码统一由你出，工程型 agent 不代写。
```

## 每条为什么在这

**1. 「提示」不要给代码**
实测过一次：练习的"提示"把答案一行一行给全了 → 结果是**跑通了，但什么也没练到**。
判断标准很简单：**提示读完，还需要自己动脑 = 合格；提示读完能直接抄 = 不合格。**

**2. 验收标准改成"合上讲义自己写"**
"跑通"是个假指标 —— 照着抄也能跑通。所以验收动作必须**关掉参考**。

**3. 示例贴近真实场景**
占位名（foo / bar / 张三）让学生记不住、也建立不起直觉；换成真实场景的名词，记忆负担立刻下降。

**4. 30–45 分钟一站**
人的反馈原话是「不喜欢一天只做一件事」——长任务容易疲劳放弃。切成小站，每天推一两站。

**5. 更新要通知工程型 agent**
时间表是另一份文件里的；材料变了不通知，时间表就会和现实脱节（这是"单一事实源"的日常维护）。

**6. 代码产出统一归教学型**
两个 agent 抢着写代码 → 风格不一致、review 成本翻倍。定成"**代码只从一个出口出**"。
