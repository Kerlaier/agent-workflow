# 三方智能体的由来

> 这份文件回答一个问题：**为什么是一个「人 + 三个 agent」的配置？**
> 下面是真实的演进过程（身份与具体数据已脱敏）。

---

## 一、起点：一个 agent 不够用

最初只有**一个** agent，负责教学：出讲义、配练习、答疑。它很称职，但很快暴露两类问题：

1. **"最后一公里"没人管**：讲义是代码文件，得变成可读的文档、要发布到仓库、要保持格式统一 —— 这不是教学 agent 的活，全堆在人身上。
2. **它自己记录自己**：它记录着进度与卡点，但**没有任何第二方核对**。

→ 加了**第二个 agent**：工程型（文档生成与发布、环境配置、近期路线）。

---

## 二、两个 agent 也还是不够

变成"两个 AI + 一个人"之后，出现了更隐蔽的问题：

- **两个都在「产出 + 自己记录」**，没有人在核对别人。
- 结果：**所有差错最后都由人兜住**。真实例子（已抽象）：
  - 同一件事在几个文件里各说各话（口径没人统一）
  - 一处问题被判定"全都有问题"，其实只有两天有
  - 口头说的边界被理解反了

→ 加了**第三个 agent**：规划型。

它的定位**不是"再来一个干活的"**，而是补两块前两个都没在做的：

| 补什么 | 为什么前两个做不了 |
|---|---|
| **长期规划** | 前两个都在处理**近期**（今天学什么、这周改什么），没人管"半年后要过哪个关口" |
| **情报** | 与长期目标相关的公开信息（时间线、窗口期、门槛）—— 前两个既没时间也没分工 |
| **质检**（**技能，不是岗位**） | 只在出现"**没人验收的产出**"时按单调用 |

> 特别注意最后一条的措辞：**质检是技能，不是岗位**。
> 把它设成岗位的后果是：它开始天天挑刺、为了产出而产出，而大部分问题当事人自己就能兜住。

---

## 三、真正的转折：从「聊天」到「文件」

加到第三个 agent 之后才意识到：**最大的问题不是 agent 不够，是协作载体错了。**

| 靠聊天协作 | 靠文件协作 |
|---|---|
| 换个会话就没了 | 状态留在磁盘上，随时可查 |
| 人必须在中间来回转述 | 各角色直接读写各自那份文件 |
| 结论只活在对话里 | 结论落成清单，可追溯 |
| 谁都可以说"我改了啊" | 每个文件有明确的 owner |

于是定下三条铁律（第四条是**踩坑之后才补的**）：

1. **写权限单点** —— 一个成品只有一个 owner
2. **单一事实源** —— 每类事实只有一个权威文件
3. **结论落文件** —— 核对结果写成清单，不靠口头转述
4. **核对事实先看旧版本**（补的）—— **检索不到 ≠ 从未存在**

## 四、演进时间线

| 时间 | 发生了什么 | 为什么这么走 |
|---|---|---|
| 07-14 | 教学型 agent 开始出讲义（第 1~10 课）+ 配套练习 | 学习需要结构化材料，不能只在聊天里问 |
| 07-17 | **文档自动生成 + 仓库发布**上线（源文件 → 文档 → 推仓库） | 讲义本身是代码，得变成能读的东西，而且要有版本 |
| 08-16 | 配置 C++ 工具链（MSYS2 + MinGW-w64），接进编辑器 | 学习路线要落到真实环境，不能停在"纸上" |
| 09-04 | 编程主线从 C++ 改到 C（对齐课程教材） | 课程教材是 C，自学路线让位 |
| 09-20 | ROS 2 环境跑通（WSL2 + Ubuntu + 一个画圆节点） | 从"语法"走到"能动手的工程" |
| 09-27 | 改掉验收标准：**关掉参考、从空白开始做** | 发现「跑通」是个假指标 —— 照着抄也能跑通 |
| 09-27 | 分工定案：**所有具体代码统一交给教学型 agent** | 两个 agent 抢着写代码 = 风格不一致 |
| 10-04 | **加入第三个 agent**；三份文件分家（协议 / 全局事实 / 长期规划） | 两个 agent 各写各记 → 没人核对 |
| 10-05 | 本仓库（脱敏版） | 把这套流程从"自己的流程"变成可展示的项目 |

## 五、哪些是设计，哪些是运气

**提前设计出来的**
- 写权限单点（一个成品一个 owner）
- 单一事实源（每类事实只有一个权威文件）

**踩了坑才补上的**
- **结论落文件** —— 原本靠聊天转述，丢过信息
- **核对事实先看旧版本** —— 原本凭"当前检索"判历史，判错过
- **计划类文档要先问再改** —— 原本以为"重出更干净"，差点覆盖掉人工改动

**还没解决的**
- 见 `docs/已知不足与教训.md`

---

## 六、一句话总结

> 不是"用了三个 AI"，而是：**给每个 agent 划一块写权限，用文件当协作层，用一条条踩坑换来的规矩约束它们。**
