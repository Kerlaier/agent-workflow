# 工具链与搭建

> 这套流程由**三个 agent + 一个人**组成。这份文件回答两个问题：**从哪装**、**怎么搭**。
> 下表的版本号是**本机实测值**（`npm ls -g --depth=0` 与各工具 `--version` 的输出），不是抄来的。

---

## 一、三个 agent 分别是什么

| 角色 | 产品 | npm 包名 | 本机实测版本 | 配置目录 |
|---|---|---|---|---|
| **教学型** | Claude Code | `@anthropic-ai/claude-code` | `2.1.209` | `~/.claude` |
| **工程型** | OpenAI Codex | `@openai/codex` | `0.158.0` | `~/.codex` |
| **规划型** | DeepSeek Harness | `@deepseek-ai/dsh` | `0.1.0-rc.6` | `~/.dsh` |

三者都以**命令行**为主；后两个另有**桌面端 App**（Electron）。
关键前提：它们跑在**同一台电脑**上、读写**同一批文件** —— 整套协作就是建立在这个前提上的。

---

## 二、前置条件

- **Node.js + npm**（三者都通过 npm 分发）
- 每个 agent 各自的**账号 / 订阅**（登录后凭据落在上表的配置目录里）
- 能访问对应服务的网络（有的服务需要自备网络环境）

---

## 三、安装步骤

### 0）先确认 Node

```bash
node -v     # 本机实测：v24.18.0
npm -v      # 本机实测：11.16.0
```

### 1）教学型 · Claude Code

```bash
npm i -g @anthropic-ai/claude-code
claude            # 首次运行按提示登录
```

配置落在 `~/.claude/`。

### 2）工程型 · OpenAI Codex

```bash
npm i -g @openai/codex
codex             # 首次运行按提示登录
```

配置落在 `~/.codex/`。

> ⚠️ **Windows 上的一个坑（真实踩过）**
> npm 生成的 `codex.cmd` 是**批处理文件**，而 Windows 的进程创建只认 `.exe` ——
> 于是**别的程序想调用它时会报「找不到 codex」**（本机当时就是被别的工具调用时暴露的）。
>
> 解法：把包内真正的 `codex.exe` 所在目录**追加到用户 PATH**：
>
> ```text
> %APPDATA%\npm\node_modules\@openai\codex\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin
> ```
>
> 注意：**npm 重装或升级这个包时，这条路径可能失效** —— 到时候重新确认一次。

### 3）规划型 · DeepSeek Harness

```bash
npm i -g @deepseek-ai/dsh
dsh --version     # 本机实测：0.1.0-rc.6
```

配置落在 `~/.dsh/`（凭据在该目录下的 `.credentials.yaml`）。桌面端 App 与命令行**可以并存**。

## 四、装完之后：最小可用的"文件层"

**光装好三个工具是不能协作的** —— 它们会各写各的、互相覆盖。还需要一层文件约定：

| 文件 | 作用 | 本仓库对应 |
|---|---|---|
| **协作协议** | 写权限边界 + 防冲突规矩 | `protocol/协作协议.md` |
| **全局事实文件** | 状态 / 决策 / 待办 / 环境记录 | `templates/交接文件模板.md` |
| **长期规划** | 长期路线（规划型 agent 唯一写手） | 自建 |
| **质检报告** | 按需产出（问题 / 证据 / 建议） | `templates/质检报告模板.md` |
| **启动提示词** | 让每个 agent 一进会话就"读到状态" | `prompts/` |

**推荐的上手顺序**：

1. **先定写权限**（谁写哪个文件），再让任何 agent 干活；
2. 给每个 agent 一份**启动提示词**，并且要求它**先复述现状、再动手**；
3. 第一件事就建**全局事实文件** —— 它是所有协作的落点；
4. 跑起来之后，把每次翻车**补成一条规矩**（这就是 `docs/已知不足与教训.md` 的来源）。

---

## 五、为什么要三个，而不是"一个全能的"

- 三个 agent 跑在同一台机器上、读写同一批文件 → **人只需要看文件**，不需要当传话筒。
- 如果只有一个：它**自己产出、自己记录、自己验收** —— **没有任何独立核对**，错误最后都由人兜住。
- 三个的成本不是钱，是**协调纪律**（本仓库其余部分讲的就是这件事）。

## 六、一句话

> 装法很普通（三条 `npm i -g`）。难的从来不是装，而是**装完之后怎么让它们不打架**。
