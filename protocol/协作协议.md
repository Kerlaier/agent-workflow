# 三方协作协议（Claude · Codex · DeepSeek）

> 建立：2026-10-04 ｜ 脱敏版：2026-10-05
> 定位：**这是「宪法」** —— 分工、写权限、报告格式都在这一份；其他文件只记事实，不重复规矩。
> 配套：`templates/交接文件模板.md`（全局事实文件的骨架）

---

## 一、为什么要有第三个 agent

原来只有两个 agent，而**两个都在「产出 + 自己记录」**，没有人独立核对 —— 所有差错最后都由**人**兜住。

真实踩到过的三类（已抽象，不含具体数据）：

1. **同一件事的数字在不同文件里对不上** —— 中间版本没人清理；
2. **把口头描述当事实** —— 「从某时刻起开始休息」被读成「某时刻之后继续排任务」，意思正好反了；
3. **范围判断过头** —— 某处问题一开始被判定「五天都有」，实际只有两天。

→ 第三个 agent 的价值落在**长期规划 + 情报**（这块前两个都没在做）。
**质检只是它的一项技能、按需调用**，不是常设岗位 —— 上面那些错，大半人自己能兜住。

## 二、分工与写权限边界

| Agent | 角色 | 可以写 | 硬禁 |
|---|---|---|---|
| **Claude Code** | 教学 + **所有具体代码** | 讲义、练习与参考答案、示例程序 | 不碰计划 / 日程文档、不碰发布 |
| **Codex** | 文档发布 + 环境配置 + **近期**路线 + 概念讲解 | 生成类文档、代码仓库、计划文档、交接类文件 | 不代写学习 / 项目代码 |
| **DeepSeek** | **长期规划 + 情报员**（常设主线）；**质检**（技能，按需） | 规划文件、报告目录、**全局事实文件**（追加式改事实）、自己工作区的日志 | 不写**成品**：文档、仓库代码、讲义；不单方面改本协议 |

**铁律：每个成品只有一个写手。** 谁都可以读，只有 owner 能改。

**脚本的边界（2026-10-05 裁定，写进这里以免再问）**

- **仓库工具 / 运维类脚本归 Codex** —— `generate_doc.py`、`build_schedule.py`、`summarize.py` 这一类；
- **学习材料与项目代码归 Claude**；
- **判据只有一条：是否含教学内容。** 含 → Claude；纯工具、只读、运维 → Codex。

**全局事实文件由三方共同维护**：谁发现里面的**事实**过时或错了，**谁直接改** —— 不许绕「报告 → 上级 → 再改」那一圈，**绕一圈等于让人当传话人**（这正是本协议要防的）。

- **改法**：只改那一条事实，**不整份重写**；动笔前先重读那一节（防覆盖别人的改动）；改完在文件末尾「更新记录」留一行。
- **本协议（规矩）不在这条里** —— 它是宪法，要改先提出来，由维护人落笔。
- **成品（文档 / 仓库代码 / 讲义）也不在这条里** —— 归各自 owner。

## 三、第三个 agent 的任务清单

### A. 长期规划（主线，常设）

- **内容**：长期目标这条路 —— 从现在到几年后要过哪些关口、每个关口要什么、什么时候做什么。
- **性质**：**持续更新**，不是一次性文档。有新情报就并进去，过时的划掉。
- **写权限**：**唯一写手**，其他人只读。

### B. 情报搜集（给规划供料）

- 与长期目标相关的**公开信息**：时间线、门槛、窗口期、往届情况。
- **只在自己被问到时给，不主动刷屏。**

### C. 质检（技能，按需调用）

- **不是岗位**，只在出现「**没人验收的产出**」时按单派活。
- **派活判据三条**（同时满足才值得派）：① 当事人自己不会去做 ② 错了会真伤到他 ③ 答案确定、能判对错。
- 适合：跨文件数字对账、成品 vs 脚本、排版逐页检查。
- **不适合**：当事人自己看得见的东西、**还没定案的事**。

## 四、防打架四条规矩

1. **写权限单点** —— 见第二节的表。第三方只读成品、只写报告。
2. **单一事实源** —— 见第五节。同一件事不在两处各写一遍。
3. **结论落文件** —— 核对结果写成 `.md` 清单，不靠聊天口头转述；由 owner 按清单改。
4. **核对事实先看旧版本** —— 想说「这段原本没有」之前先翻**备份 / 旧版本**。**检索不到 ≠ 从未存在**（很可能是别人刚改掉的）；**行号会漂移**，定位一律用「章节名 + 原文片段」。

## 五、单一事实源

| 内容 | 唯一权威文件 |
|---|---|
| 规矩（分工、写权限、报告格式） | 本文件 |
| 全局状态 / 进度 / 决策 | `交接文件.md`（骨架见 `templates/`） |
| 长期规划 / 路线 | `长期规划.md`（规划型 agent 写，其他人只读） |
| 领域待办（如某张表的修订意见） | 各自的领域清单文件 |

**规矩：谁改了事实，谁更新对应文件。** 别让人当传话人。

---

## 六、产出落点与命名

- **长期规划**：持续更新的单一文件，不是报告。
- **质检报告**：放报告目录，命名 `质检报告-YYYYMMDD-主题.md`。
- 每份质检报告只要三块：**① 发现的问题 ② 证据（原话 / 文件 / 片段）③ 建议怎么改**。
- **报告写完不改成品**，等 owner 处理。

---

## 七、环境与工作区

- 三个 agent 都能读写本地文件；**能力边界先验证再用**（例如某些列目录的命令其实只列文件）。
- **工作区可以有重叠，写权限不能重叠。**
- 涉及发布 / 改成品时 → 一律转对应 owner，不要自己动手。
