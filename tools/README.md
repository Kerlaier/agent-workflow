# tools/

`summarize.py` —— 读一组 markdown，输出「待办 + 最近更改」摘要。

**性质**：只读工具。**不联网、不调用模型 API、不写回任何源文件**，结果打到 stdout。

## 用法

```bash
python summarize.py --files "protocol/*.md" "docs/*.md" --recent 10
python summarize.py --files "**/*.md" --recent 3
```

| 参数 | 说明 |
|---|---|
| `--files` | 一个或多个文件 / glob 模式（`**` 支持递归） |
| `--recent` | 每个文件最多取多少条更新记录，默认 10；`0` = 全部 |

## 输出长什么样

```text
# 摘要

> 生成时间：2026-10-05 10:58｜扫描 12 个文件

## 待办

共 **9** 项未完成。

### prompts/03-工程型-发布前自检.md

- [ ] **有没有把"承诺"写成"已完成"？**
- [ ] **数字和来源文件对得上吗？**

## 最近更改

### templates/交接文件模板.md

- YYYY-MM-DD HH:MM｜<谁>｜把 §X 的「<原文片段>」改成「<新内容>」；依据：<来源>
```

## 两个设计决定（不是随手写的）

- **取末尾 N 条，不按时间戳排序**：更新记录是**追加式**的，最后写的就是最新的。
  时间戳可能缺失、也可能彼此不一致（真实踩过这个坑），所以**不拿它当排序依据**。
- **找不到小节就跳过，不报错**：仓库里大部分文件本来就没有「更新记录」；
  报错会让工具没法用。被跳过的文件会在末尾统一列出来。

## 它不做什么（刻意不做）

- 不解析正文语义、不做冲突检测、不做并发写保护 —— 只做**文本层面的收集**。
- 不改任何文件。要改，是对应 owner 看了摘要之后自己去改。

## 维护

生成类 / 工具类脚本由**工程型 agent** 维护（它同时负责文档生成与发布这条线）。
